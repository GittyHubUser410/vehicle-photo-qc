# v0.2A acceptance and regression tests

v0.2A is not complete until these tests pass or an explicit limitation is documented.

## Automated baseline

Continue running:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check app\backend ml tests scripts
Push-Location app\frontend
npm.cmd run build
Pop-Location
```

Run Playwright/browser tests with the disposable test server.

## Database migration tests

Test at least:

1. Fresh SQLite schema creates correctly.
2. Existing schema-v3 SQLite dataset opens unchanged.
3. SQLite -> PostgreSQL migration preserves:
   - conglomerates,
   - dealerships,
   - photographers,
   - shoots,
   - photos,
   - runs/metrics/issues,
   - review events,
   - training examples/revisions,
   - datasets,
   - model-version metadata,
   - shot catalog,
   - dealer-sequence memory,
   - trash/delete state.
4. Row-count checks match expected counts.
5. Foreign-key relationships remain valid.
6. Important IDs remain stable.
7. Existing file paths still resolve.
8. Migration failure leaves source SQLite untouched.
9. Re-running migration has clearly defined behavior and cannot silently duplicate rows.

## Concurrency tests

Simulate multiple users.

Required cases:

- 4 users stage uploads at the same time.
- 4 users commit distinct vehicles.
- No photo crosses into another user's shoot.
- Two users edit the same vehicle metadata: stale save is rejected or safely merged.
- Two users edit training labels: stale revision is rejected.
- Two users resolve/reopen reviews without losing event history.
- Shot-type reorder/archive during another read/write does not corrupt catalog order.
- Delete/restore remains consistent under overlapping reads.

## Analysis queue tests

- Submit at least 4 vehicles rapidly.
- API remains responsive while analysis runs.
- Jobs execute once.
- Restart during queued work recovers jobs.
- Restart during processing does not duplicate final runs.
- Failed job can be retried.
- Existing historical analysis runs remain intact.

## Authentication / role tests

Verify server-side access for each role.

### Admin
- manage users,
- change roles,
- edit setup,
- delete/restore,
- review/training actions.

### Manager
- operational setup/review/training actions,
- cannot perform forbidden admin-only actions if any.

### Reviewer / Trainer
- review/training actions,
- cannot change protected setup/admin state.

### Standard User
- can upload and use intended operational views,
- cannot perform restricted destructive/admin actions.

Also test:

- disabled/unknown user,
- local test identity,
- Cloudflare identity mapping,
- direct API request bypass attempts.

## Audit tests

For every required audited action:

- actor is correct,
- target is correct,
- timestamp exists,
- action type is stable,
- before/after payload is sufficient,
- no secret tokens/passwords are stored.

## Remote/pilot manual tests

On real devices:

- PC browser.
- Android phone portrait.
- Android phone landscape.
- At least two devices logged in simultaneously.
- Rare 3–4 concurrent uploads.
- Refresh during upload.
- Temporary network interruption.
- Host restart.

## Startup/recovery manual test

1. Shut down app normally.
2. Reboot Windows.
3. Confirm backend and tunnel become reachable without manually opening developer terminals.
4. Confirm data directory is correct.
5. Confirm Cloudflare access still protects the app.
6. Confirm no duplicate worker starts.
7. Confirm logs make startup failure understandable.

## Regression checks

Verify no regression in:

- phone portrait viewer,
- thumbnail score display,
- shot-type search,
- shot-type add/rename/reorder/archive/restore,
- vehicle metadata editing,
- training membership,
- training labels/defaults,
- copy/paste labels,
- dealer sequence memory,
- trash/restore,
- review queue/history,
- downloads/readable filenames,
- Cloudflare remote upload staging,

- model files/activation metadata.
